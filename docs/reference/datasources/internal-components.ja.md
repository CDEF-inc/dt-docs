# 内部コンポーネント

Dependency-Track では、組織が特定のコンポーネントの名前空間と名前を*内部*としてマークできます。内部として識別されたコンポーネントは、すべての外部サービスから除外されます。外部の脆弱性アナライザー(OSS Index、Snyk、Trivy、VulnDB)に送信されることはなく、公開パッケージリポジトリに照会されることもありません。

これは、SBOM に自社製のライブラリが含まれていて、その座標が公開パッケージと一致する可能性がある場合や、内部パッケージに関するメタデータをネットワークの外に出してはならない場合に役立ちます。

## 照合のしくみ {#how-matching-works}

内部コンポーネントの識別は、**Administration > Internal components** で 1 つ以上の名前空間と名前のパターンを指定して設定します。

照合モードは 2 つあります。

| モード | 動作 |
|:-----|:---------|
| OR(デフォルト) | 名前空間または名前のいずれかが、設定されたいずれかのパターンに一致する場合、コンポーネントは内部とみなされます。 |
| AND | 名前空間と名前の両方が一致する場合、コンポーネントは内部とみなされます。 |

パターンは、コンポーネントの PURL の名前空間フィールドと名前フィールドに対して照合されます。

!!! note
    デフォルトでは、内部として識別されるコンポーネントはありません。すべてのコンポーネントはサードパーティとして扱われ、設定された外部アナライザーに送信される可能性があります。

## 内部としてマークされた場合の影響 {#effects-of-being-marked-internal}

| サービス | 内部コンポーネントに対する動作 |
|:--------|:---------------------------------|
| OSS Index | 照会されない |
| Snyk | 照会されない |
| Trivy | 照会されない |
| VulnDB | 照会されない |
| 公開パッケージリポジトリ | バージョンの鮮度チェックのために照会されない |
| 内部アナライザー | 引き続きローカルの脆弱性データベースに対して評価される |
| 非公開リポジトリ | 設定されていれば引き続き照会される |

## 非公開の脆弱性リポジトリとの併用 {#use-with-the-private-vulnerability-repository}

内部コンポーネントも、[非公開の脆弱性リポジトリ](private-vulnerability-repository.md)で定義された脆弱性とは引き続き照合できます。これにより、組織はコンポーネントの識別子を外部に公開することなく、自社のコードベースの脆弱性を追跡してトリアージできます。
