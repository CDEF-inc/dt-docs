# 脆弱性データソース

脆弱性データソースは、Dependency-Track が内部の脆弱性データベースを構築する際の上流のフィードです。[内部アナライザー](../analyzers.md#internal)は脆弱性分析の際にこのローカルデータベースを照会するため、分析時には外部への呼び出しは発生せず、外部への呼び出しはミラーリングの際にのみ発生します。

各データソースが提供するものと、それらの間のトレードオフの背景については、[脆弱性データソースについて](../../concepts/about-vulnerability-data-sources.md)を参照してください。ミラーリングを有効にしてスケジュールを設定する手順については、[脆弱性データソースを設定する](../../guides/administration/configuring-vulnerability-sources.md)を参照してください。

## ミラーリングされるデータソース {#mirrored-sources}

Dependency-Track は、3 つの公開データソースをローカルデータベースにミラーリングできます。ミラーリングは設定可能なスケジュール(デフォルトでは毎日)で実行されるほか、Dependency-Track が初めてタスクをスケジュールした直後にも 1 回実行されます。進行状況とエラーは API サーバーのログに書き込まれます。

| データソース | 識別子のプレフィックス | 照合の対象 |
|:-------|:------------------|:-----------|
| NVD | `CVE-` | CPE |
| GitHub Advisories | `GHSA-` | PURL |
| OSV | エコシステムによって異なる | PURL |

## その他のデータソース {#other-sources}

| データソース | 説明 |
|:-------|:------------|
| [非公開の脆弱性リポジトリ](private-vulnerability-repository.md) | 独自のコンポーネントや公開前の調査のために、社内で管理する脆弱性です。 |
| [パッケージリポジトリ](repositories.md) | 古くなったコンポーネントの検出に使うパッケージレジストリとの連携です。脆弱性のデータソースではありません。 |
| [内部コンポーネント](internal-components.md) | 外部サービスに決して送信してはならないコンポーネントをマークします。 |

## 外部サービスを照会するアナライザー {#analyzers-that-query-external-services}

OSS Index、Snyk、Trivy、VulnDB は、分析時に外部 API を呼び出す*アナライザー*です。これらについては、[脆弱性アナライザー](../analyzers.md)のリファレンスで別途説明しています。
