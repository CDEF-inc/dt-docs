# タグについて

**タグ**は、短い共有のラベルです。同じタグを[プロジェクト](projects.md)、[コンポーネント](component-policies.md)ポリシーと[脆弱性](vulnerability-policies.md)ポリシー、脆弱性、[アラート](notifications.md)に付けることができ、システムの他の部分はタグを読み取って動作の範囲を決めます。タグは意図的に軽量に作られており、名前以外は何も持ちません。

## タグとは {#what-a-tag-is}

タグは名前です。名前はインスタンス全体で一意なので、同じ名前を 2 か所に付けると、それらは同じタグを指します。タグには値も、型も、名前空間も、説明もありません。プロジェクトにより豊富なメタデータを結び付ける必要がある場合は、代わりに[プロジェクトのプロパティ](projects.md#tags-and-properties)を使ってください。

タグと、タグが付けられる対象は多対多の関係です。1 つのプロジェクトは多数のタグを持つことができ、1 つのタグは多数のプロジェクトに付けることができます。あるプロジェクトからタグを外しても、他のプロジェクトには影響しません。

## タグの役割 {#what-tags-do}

タグは範囲を指定するための基本要素です。システムのさまざまな部分が、同じタグの集合を参照します。

- **プロジェクトの絞り込み**。プロジェクト一覧はタグで絞り込めます。
- **ポリシーの割り当て**。コンポーネントポリシーや脆弱性ポリシーは、特定のタグを持つプロジェクトだけを対象にできます。[コンポーネントポリシーについて](component-policies.md)と[脆弱性ポリシーについて](vulnerability-policies.md)を参照してください。
- **コレクションプロジェクト**。タグベースのコレクションモードは、設定したタグを持つ子だけを集約します。[プロジェクトについて › コレクションプロジェクト](projects.md#collection-projects)を参照してください。
- **アラート**。[アラート](notifications.md)は、特定のタグを持つプロジェクトについてだけ発火するように設定できます。
- **脆弱性へのタグ付け**。トリアージやレポートのために、脆弱性にタグを付けることができます。

## タグとプロジェクトのプロパティの比較 {#tags-versus-project-properties}

どちらもプロジェクトにメタデータを付けるものですが、答える問いが異なります。

- 値が多数のプロジェクトに当てはまる可能性のあるラベルで、ポリシーエンジン、アラート、タグで絞り込むコレクションモードがそれを読み取ることを想定している場合は、**タグ**を使います。
- 値がプロジェクトごとの構造化データ(型付きのキーと値)で、後から読み返したいものの、組み込みの機能がそれを利用しない場合は、**プロジェクトのプロパティ**を使います。

プロパティは型とグループ名を持ちますが、タグは持ちません。1 つのタグに 2 つの情報を詰め込もうとしている(`team:platform`、`env=prod`)なら、代わりにプロパティを使うか、2 つの別々のタグを使うべきだというサインです。

## ライフサイクル {#lifecycle}

タグは、最初に使われたときに暗黙的に作成されます。存在しない名前を付けると、そのタグが作成されます。最後の付与を外すと孤立したタグが残り、メンテナンスタスクが次回の実行時にそれをクリーンアップします。タグにはタグごとのアクセス制御はありません。プロジェクトを編集できるユーザーは誰でも、そのプロジェクトにタグを付けることもできます。
