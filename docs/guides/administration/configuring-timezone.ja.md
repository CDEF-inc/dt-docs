# タイムゾーンを設定する

!!! note
    UTC 以外のタイムゾーンで API サーバーを実行するには、Dependency-Track **5.0.1 以降**が必要です。バージョン 5.0.0 は暗黙的に UTC を前提としており、それ以外のタイムゾーンでは正しく動作しません。

Dependency-Track は、内部での日付と時刻の処理をすべて UTC で行います。公式のコンテナーイメージもそれに合わせて `TZ=Etc/UTC` を設定しています。`TZ` は、システムのタイムゾーンを表す標準の POSIX 環境変数です。これを UTC 以外の値に設定しても、変わるのは API サーバーの `stdout` と `stderr` におけるログのタイムスタンプの表示だけです。保存されたデータ、ダッシュボード、ポリシー、REST のレスポンスは UTC のままです。

!!! tip
    可能であれば、API サーバーは UTC で実行してください。ログの行、パーティション名、ダッシュボードの集計単位は、同じタイムゾーンを共有しているほうが突き合わせやすくなります。

## `TZ` を設定する {#setting-tz}

API サーバーのコンテナーに環境変数として `TZ` を設定します。

```yaml linenums="1" title="docker-compose.yaml"
services:
  apiserver:
    image: dependencytrack/apiserver
    environment:
      TZ: "Europe/Paris"
```

任意の [IANA タイムゾーン識別子][iana-tz]を使えます。不明な識別子を指定すると、エラーにならずに `GMT` にフォールバックします。

## データベースセッションのタイムゾーン {#database-session-time-zone}

API サーバーの PostgreSQL セッションは `TZ` を引き継ぎます。これは保存されるデータには影響しません。書き込みは絶対的な時点として行われ、パーティションのメンテナンスとマテリアライズドビューのリフレッシュでは、それぞれのトランザクションでセッションを UTC に固定します。

!!! warning
    データベースに直接接続する場合は、セッションのタイムゾーンを API サーバーの `TZ` に合わせてください。PostgreSQL は、`timestamptz` をセッションのタイムゾーンで表示し、タイムゾーンが指定されていない日付やタイムスタンプのリテラルをそのタイムゾーンで解釈し、比較もそのタイムゾーンを介してキャストします。タイムゾーンが一致していないと、読み取り時には同じ行が数時間ずれて見え、書き込み時には誤った時点が気付かないうちに挿入されます。アドホックな更新を実行する前に、`SET TimeZone TO '<zone>'` を発行してください。

[iana-tz]: https://en.wikipedia.org/wiki/List_of_tz_database_time_zones
