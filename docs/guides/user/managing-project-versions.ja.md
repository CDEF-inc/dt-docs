# プロジェクトのバージョンを管理する

プロジェクトは名前とバージョンの組み合わせで識別されます。リリースの履歴を追跡するには、名前が同じでバージョン文字列が異なる兄弟プロジェクトを作成し、現在のものを最新としてマークし、最終的に古いものを廃止します。

Dependency-Track がバージョン文字列を不透明な値として扱うことを含め、バージョンがモデル全体の中でどのように位置付けられるかについては、[プロジェクトについて › バージョン](../../concepts/projects.md#versions)を参照してください。このガイドの操作には、ポートフォリオ管理の権限が必要です。正確な権限の組み合わせについては、リファレンスの[権限](../../reference/permissions.md)を参照してください。

## 新しいバージョンか、上書きか {#new-version-or-overwrite}

リリース後にプロジェクトを更新する方法は 2 つあります。

- **同じ名前とバージョンで新しい BOM をアップロードする。** Dependency-Track はコンポーネントの一覧を同一性によって照合します。一致するコンポーネントは(監査の判断とともに)そのまま残り、BOM に含まれなくなったコンポーネントは削除され、新しいコンポーネントが追加されます。分析が再実行され、プロジェクトは同一性を保ちます。未リリースのバージョンや継続的に更新されるバージョン(`dev` や `main` のライン)をその場で更新する場合に使用します。
- **新しいバージョンを作成する。** 既存のプロジェクトをそのリリースの記録として保存し、次のリリースは別に追跡を始めます。後から振り返る予定のあるすべてのリリースに使用します。

このガイドの残りの部分では、2 つ目の方法について説明します。

## 新しいバージョンにクローンする {#clone-to-a-new-version}

新しいバージョンを始める最も早い方法は、既存のバージョンをクローンすることです。クローンすると、同じ名前で、指定したバージョンを持つ兄弟プロジェクトが新たに作成されます。

1. 元のプロジェクトを開きます。
2. プロジェクト名の横にあるプロジェクトのバージョンを選択し、*Add Version* オプションを選んで、バージョン作成のモーダルを開きます。
3. 新しい *Version* 文字列を入力します。
4. 引き継ぐ内容を選びます。
    - *Tags*: プロジェクトのタグをクローンにも残します。
    - *Properties*: カスタムのキーと値のプロパティをコピーします。
    - *Components*: コンポーネントの一覧をコピーします。
    - *Services*: 元のプロジェクトで宣言されているサービスをコピーします。
    - *Findings*: 脆弱性の検出結果をコピーします。
    - *Findings audit history*: 検出結果の分析の判断(分析状態、根拠、コメント、抑制)を引き継ぎます。
    - *Policy violations*: ポリシー違反をコピーします。
    - *Policy violation audit history*: ポリシー違反の分析の判断(状態、コメント、抑制)を引き継ぎます。
    - *Access control list*: 元のプロジェクトのアクセスリストを引き継ぎます。
    - *Is latest version*: 新しいバージョンを最新としてマークし、それまで最新だったバージョンのフラグを解除します。
5. 保存します。

!!! tip
    一部のオプションは互いに依存しています。たとえば、コンポーネントを含めずに検出結果だけを含めることはできません。フォームはこれらの依存関係に基づいてオプションを自動的に切り替えます。

*Components* を選ばなかった場合、クローンは空の状態で始まり、次の BOM のアップロードでコンポーネントが登録されます。新しいバージョンの BOM が直後に CI から届く場合は、この方法を使用します。

クローンでは行単位でコピーするため、コンポーネントと監査履歴を含むプロジェクトのクローンにかかる時間は、プロジェクトの規模に比例します。大規模なプロジェクトでは、操作にかなりの時間がかかることを想定してください。CI が直後にコンポーネントを再登録する場合は、コンポーネントを含めずにクローンすることをお勧めします。

## バージョンを最新としてマークする {#mark-a-version-as-latest}

*latest version* フラグは手動で設定します。Dependency-Track はバージョン文字列からフラグを推測しません。次の 2 か所のいずれかで設定します。

- *Add Version* モーダルの *Is latest version* トグル(最も一般的な方法)。
- *Project Details* モーダルの *General* タブにある *Is latest version* トグル。

フラグを持つのは、プロジェクト名ごとに最大 1 つのバージョンです。新しいバージョンを最新としてマークすると、それまで最新だったバージョンのフラグが解除されます。

このフラグは、最新バージョンのコレクションモード([プロジェクトを階層に整理する](organizing-projects.md#choose-a-collection-logic)を参照)と、バージョンを指定せずに名前でプロジェクトを解決するバッジの URL で使用されます。

:star: アイコンは、そのプロジェクトのバージョンが*最新*であることを示します。

![バージョンのドロップダウン](../../assets/images/guides/user/managing-project-versions/version-dropdown.png)

## 古いバージョンを廃止する {#retire-an-old-version}

リリースが本番環境で使われなくなったら、そのプロジェクトを非アクティブにします。そのためには、*Project Details* を開き、*General* タブで *Active* をオフにします。プロジェクトにアクティブな子がある間は、このトグルは使用できません。先に子を非アクティブにしてください。

プロジェクトを非アクティブにすることの意味(表示、親子関係、保持による削除の対象)については、[プロジェクトについて › アクティブなプロジェクトと非アクティブなプロジェクト](../../concepts/projects.md#active-and-inactive-projects)を参照してください。

![Active トグル](../../assets/images/guides/user/managing-project-versions/active-toggle.png)

非アクティブなプロジェクトは、*Show inactive projects* をオンにすれば誰でも参照できます。Dependency-Track は、保持の設定によって削除されるまで、それらの監査履歴、タグ、プロパティ、アクセスリストを保持します。

![一覧に表示された非アクティブなプロジェクト](../../assets/images/guides/user/managing-project-versions/inactive-projects-listed.png)

## 廃止したバージョンの自動削除 {#automatic-deletion-of-retired-versions}

保持を設定すると、メンテナンスタスクが廃止したバージョンをスケジュールに従って削除します。保持の基準は、経過日数(N 日より古い非アクティブなプロジェクトを削除する)またはバージョン数(名前ごとに直近 N 個の非アクティブなバージョンを残す)です。[プロジェクトの保持期間を設定する](../administration/configuring-project-retention.md)を参照してください。保持の対象は非アクティブなプロジェクトだけです。アクティブなプロジェクトは影響を受けません。
