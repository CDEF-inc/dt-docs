# v0.7.0-alpha.3 へのアップグレード

* **脆弱性ポリシーの REST API エンドポイントが v1 から v2 に移行しました。** 次の v1 エンドポイントは削除されました。

    | 削除されたエンドポイント | 代替 |
    |:---------------------------------------------|:--------------------------------------|
    | `GET /api/v1/policy/vulnerability`           | `GET /api/v2/vuln-policies`           |
    | `GET /api/v1/policy/vulnerability/{uuid}`    | `GET /api/v2/vuln-policies/{uuid}`    |
    | `PUT /api/v1/policy/vulnerability`           | `POST /api/v2/vuln-policies`          |
    | `POST /api/v1/policy/vulnerability`          | `PUT /api/v2/vuln-policies/{uuid}`    |
    | `DELETE /api/v1/policy/vulnerability/{uuid}` | `DELETE /api/v2/vuln-policies/{uuid}` |
    | `GET /api/v1/policy/vulnerability/bundle`    | `GET /api/v2/vuln-policy-bundles`     |

    脆弱性ポリシーは、外部のバンドルを必要とせずに REST API から直接作成・管理できるようになりました。バンドルで管理しているポリシーも引き続き動作します。

* **脆弱性ポリシーは、1 つのポリシーにつき 1 つの条件のみをサポートするようになりました。** 以前は、1 つのポリシーに複数の条件を定義できました。アップグレード中に、各ポリシーの最初の条件だけが保持されます。複数の条件に依存していたポリシーは、別々のポリシーに分割する、または CEL 式を使って条件を組み合わせるなどの方法で、構成し直す必要があります。

* **脆弱性ポリシーのバンドルを取得する際の S3 のサポートが削除されました。** 次の設定プロパティは認識されなくなりました。

    | 削除されたプロパティ |
    |:-----------------------------------------|
    | `dt.vulnerability.policy.s3.access.key`  |
    | `dt.vulnerability.policy.s3.secret.key`  |
    | `dt.vulnerability.policy.s3.bucket.name` |
    | `dt.vulnerability.policy.s3.bundle.name` |
    | `dt.vulnerability.policy.s3.region`      |

    これまで S3 からバンドルを取得していたデプロイでは、HTTP(S) でバンドルを配信するように切り替え、代わりに `dt.vulnerability.policy.bundle.url` を使用する必要があります。

* **設定プロパティ `dt.vulnerability.policy.bundle.source.type` が削除されました。** バンドルの取得は HTTP(S) のみをサポートするようになりました。`dt.vulnerability.policy.bundle.url` に HTTP(S) の URL がすでに設定されている場合、代わりの設定は不要です。

* **設定プロパティ `dt.vulnerability.policy.analysis.enabled` が削除されました。** ポリシーが存在する場合、脆弱性ポリシーの分析は常に有効になりました。

* 脆弱性ポリシーのバンドルを同期するタスクの設定名が変更されました。

    | 変更前 | 変更後 |
    |:-------------------------------------------------------|:------------------------------------------------|
    | `dt.task.vulnerability.policy.fetch.cron`              | `dt.task.vulnerability-policy-bundle-sync.cron` |
    | `dt.task.vulnerability.policy.fetch.lock.max.duration` | *(削除)*                                        |
    | `dt.task.vulnerability.policy.fetch.lock.min.duration` | *(削除)*                                        |

    デフォルトの同期間隔は、5 分ごとから 15 分ごとに変更されました。

* **Fortify SSC、DefectDojo、Kenna Security のシークレットと、パッケージリポジトリのパスワードは、[シークレット管理](../administration/configuring-secret-management.md)に移行されました。** アップグレード中に、Fortify SSC のトークン、DefectDojo の API キー、Kenna Security のトークンはデータベースから消去され、パスワードが保存されているパッケージリポジトリはオフになります。アップグレード後に、シークレット管理のプロバイダーで必要なシークレットを設定し、影響を受けたパッケージリポジトリを手動で再び有効にしてください。

* **ベアラートークンが JWT から不透明なトークンに変更されました。** アップグレード時に、既存のユーザーセッションはすべて無効になります。ユーザーは再度ログインする必要があります。セッションタイムアウトの設定プロパティの名前が変更されました。

    | 変更前 | 変更後 | デフォルト |
    |:---------------------------|:-----------------------------|:---------|
    | `dt.auth.jwt.ttl.seconds`  | `dt.auth.session-timeout-ms` | 28800000 |

    デフォルトのセッションの有効期間は、7 日から 8 時間に変更されたことに注意してください。以前のデフォルトに依存していたデプロイや、`dt.auth.jwt.ttl.seconds` を明示的に設定していたデプロイでは、それに応じて設定を更新する必要があります。

* **5.6.0 で導入されたロールの仕組みが削除されました**。この仕組みは[意図どおりに動作したことがなく](https://github.com/DependencyTrack/hyades/issues/2116)、既存の認可の仕組みを弱めており、システムに大きな破壊的変更を加えずに修正することはできません。
* サポートされる PostgreSQL の最小バージョンが 13 から 14 に引き上げられました([hyades/#1910])。
* **Kafka は不要になりました**。プラットフォームは PostgreSQL だけで動作できるようになり、別途メッセージブローカーを用意する必要はなくなりました。非同期処理の大部分は、[永続実行](../../concepts/architecture/design/durable-execution.md)モデルに移行されました。
* **vulnerability-analyzer サービスが削除されました**。脆弱性分析は API サーバーで実行されるようになりました。詳しくは[設計ドキュメント](../../concepts/architecture/design/vulnerability-analysis.md)を参照してください。
* **repository-meta-analyzer サービスが削除されました**。パッケージメタデータの解決は API サーバーで実行されるようになりました。詳しくは[設計ドキュメント](../../concepts/architecture/design/package-metadata-resolution.md)を参照してください。
* **notification-publisher サービスが削除されました**。通知の発行は API サーバーで実行されるようになりました。詳しくは[設計ドキュメント](../../concepts/architecture/design/notifications.md)を参照してください。
* 通知のパブリッシャーとアラートの内部的な設定方法が変更されました。
    * 既存の設定は、アップグレード中にベストエフォートで移行されます。
    * 部分的に移行されたアラートの設定が有効になるのを防ぐため、**アップグレード中にすべてのアラートがオフになります**。
    * アップグレード後に、アラートを手動で確認して再び有効にする必要があります。
    * 手順については、[パブリッシャーのドキュメント](../../reference/notifications/publishers.md)を参照してください。
* **通知はデフォルトでは Kafka に発行されなくなりました**。今後は、アラートを明示的に設定する必要があります。Kafka 経由で通知を受け取りたい場合は、新しい [Kafka パブリッシャー](../../reference/notifications/publishers.md#kafka)を使用してください。
* UI のメールサーバーの設定は、`Administration → General → Email` から `Administration → Notifications → Publishers → Email` に移動しました。アップグレード中に**以前に設定したメールの設定は破棄される**ため、メールによる通知の送信に依存している場合は、設定し直す必要があります。
* API サーバーの次のデータベース設定は非推奨になりました。

    | 変更前 | 変更後 |
    |:------------------------------------|:-------------------------------------|
    | `alpine.database.url`               | `dt.datasource.url`                  |
    | `alpine.database.username`          | `dt.datasource.username`             |
    | `alpine.database.password`          | `dt.datasource.password`             |
    | `alpine.database.pool.enabled`      | `dt.datasource.pool.enabled`         |
    | `alpine.database.pool.max.size`     | `dt.datasource.pool.max-size`        |
    | `alpine.database.pool.min.idle`     | `dt.datasource.pool.min-idle`        |
    | `alpine.database.pool.idle.timeout` | `dt.datasource.pool.idle-timeout-ms` |
    | `alpine.database.pool.max.lifetime` | `dt.datasource.pool.max-lifetime-ms` |

    * このバージョンでは、`dt.datasource.*` の設定のデフォルト値は、対応する `alpine.database.*` の値になります。既存のデプロイは変更なしで引き続き動作するはずです。`alpine.database.*` の設定のサポートは、GA リリースまでに削除されます。
    * 新しいデータソースの設定の仕組みについては、[データソースの設定リファレンス](../../reference/configuration/datasources.md)で説明しています。

* **すべての設定プロパティが、`dt.` プレフィックスを使うように統一されました**。これまで `alpine.` プレフィックスを使っていたプロパティや、プレフィックスがなかったプロパティは、`dt.` の下に移りました。例:

    | 変更前 | 変更後 |
    |--------------------------------------|-----------------------------------------|
    | `alpine.ldap.enabled`                | `dt.ldap.enabled`                       |
    | `alpine.oidc.enabled`                | `dt.oidc.enabled`                       |
    | `task.portfolio.metrics.update.cron` | `dt.task.portfolio.metrics.update.cron` |

    * 名前の付け方の規則は単純です。
        * `alpine.<suffix>` → `dt.<suffix>`(以前の `alpine.*` プロパティすべて)
        * `<name>` → `dt.<name>`(以前はプレフィックスがなかったプロパティすべて)

    環境変数を使う場合も、同じ対応関係が適用されます。`ALPINE_LDAP_ENABLED` は `DT_LDAP_ENABLED` に、`TASK_PORTFOLIO_METRICS_UPDATE_CRON` は `DT_TASK_PORTFOLIO_METRICS_UPDATE_CRON` になります。ほかも同様です。

    すぐに対応する必要はありません。古いプロパティ名と環境変数はフォールバックの仕組みによって引き続き動作しますが、非推奨であり、将来のリリースで削除されます。できるだけ早く設定を更新してください。

* **ヘルスとメトリクスのエンドポイントは、専用の管理サーバーに移動しました**。管理サーバーは別のポート(デフォルトは `9000`)で待ち受けます。管理サーバーは[初期化タスク](../../reference/configuration/init-tasks.md)より前に起動するため、起動シーケンス全体を通じてヘルスプローブを利用できます。

    | エンドポイント | 変更前 | 変更後 |
    |:----------|:------------------------------------|:------------------------------------|
    | ヘルス | `http://<host>:8080/health`         | `http://<host>:9000/health`         |
    | Liveness  | `http://<host>:8080/health/live`    | `http://<host>:9000/health/live`    |
    | Readiness | `http://<host>:8080/health/ready`   | `http://<host>:9000/health/ready`   |
    | Startup   | `http://<host>:8080/health/started` | `http://<host>:9000/health/started` |
    | メトリクス | `http://<host>:8080/metrics`        | `http://<host>:9000/metrics`        |

    詳しくは[オブザーバビリティのドキュメント](../administration/configuring-observability.md)を参照してください。

* **環境変数 `LOGGING_LEVEL` が削除されました**。ログレベルは、ロガーごとの `dt.logging.level."<logger-name>"` プロパティで設定するようになりました。詳しくは[ログのドキュメント](../administration/configuring-observability.md#adjusting-log-levels)を参照してください。
* 次の初期化タスクの設定は削除され、`init.tasks.datasource.name` に置き換えられました。
    * `init.tasks.database.url`
    * `init.tasks.database.username`
    * `init.tasks.database.password`
* 現在の初期化タスクのデータソースの設定について詳しくは、[初期化タスク](../../reference/configuration/init-tasks.md#data-source)を参照してください(このリリースでは `init.tasks.datasource.name` を使用します)。
