# v0.6.0 へのアップグレード

* ネイティブの Kafka プロパティとの衝突を防ぐため、設定 `kafka.topic.prefix` の名前が `dt.kafka.topic.prefix` に変更されました([hyades/#1392])。
* タスクの cron 式とロック期間の設定名が変更されました([apiserver/#840])。設定名は、一貫した `task.<task-name>.<config>` の形式に従うようになりました。ロック期間は、ミリ秒ではなく [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601#Durations) 形式で指定するようになりました。名前の変更の例:

    | 変更前 | 変更後 |
    |:------------------------------------------------|:--------------------------------------------------|
    | `task.cron.metrics.portfolio`                   | `task.portfolio.metrics.update.cron`              |
    | `task.metrics.portfolio.lockAtMostForInMillis`  | `task.portfolio.metrics.update.lock.max.duration` |
    | `task.metrics.portfolio.lockAtLeastForInMillis` | `task.portfolio.metrics.update.lock.min.duration` |

* REST API エンドポイント `/api/v1/vulnerability/source/{source}/vuln/{vuln}/projects` がページネーションをサポートするようになりました([apiserver/#888])。ほかのページネーション対応のエンドポイントと同様に、ページサイズのデフォルトは `100` です。現在*すべて*の項目が一度に返されることを前提としているクライアントは、ページネーションに対応するよう更新する必要があります。
* API サーバーの Kafka プロセッサーのプロパティから `alpine.` プレフィックスが削除されました([apiserver/#904])。名前の変更の例:

    | 変更前 | 変更後 |
    |:-----------------------------------------------------------|:----------------------------------------------------|
    | `alpine.kafka.processor.vuln.scan.result.processing.order` | `kafka.processor.vuln.scan.result.processing.order` |

* v4.x で非推奨になっていた次のエンドポイントが削除されました([apiserver/#910])。

    | 削除されたエンドポイント | 代替 |
    |:---------------------------------------------------|:-----------------------------------|
    | `POST /api/v1/policy/{policyUuid}/tag/{tagName}`   | `POST /api/v1/tag/{name}/policy`   |
    | `DELETE /api/v1/policy/{policyUuid}/tag/{tagName}` | `DELETE /api/v1/tag/{name}/policy` |
    | `GET /api/v1/tag/{policyUuid}`                     | `GET /api/v1/tag/policy/{uuid}`    |
    | `GET /api/v1/bom/token/{uuid}`                     | `GET /api/v1/event/token/{uuid}`   |

* 必要な PostgreSQL のバージョンが 11 から 13 に引き上げられました([hyades/#1724])。それより前のバージョンでも動作する可能性はありますが、テストは行われなくなりました。

* データベースのユーザーレコードは、別々の `LDAPUSER`、`MANAGEDUSER`、`OIDCUSER` テーブルから、1 つの `USER` テーブルに統合されました([apiserver/#1169])。新しい `USER` テーブルでは、ユーザー名の一意性が強制されます。データの損失を防ぐため、ユーザー名が衝突する `LDAPUSER` と `OIDCUSER` のレコードには、それぞれ `-CONFLICT-LDAP` と `-CONFLICT-OIDC` のサフィックスが値に付加されます。影響を受けるユーザーは認証できません。管理者は、必要に応じてユーザーを削除するか名前を変更して、これを解決してください。これはエッジケースであり、ほとんどのデプロイには影響しないはずです。

* メトリクスのテーブル `DEPENDENCYMETRICS`、`PORTFOLIOMETRICS`、`PROJECTMETRICS` は、日付でパーティション分割されます([apiserver/#1141])。マイグレーションの手順では既存のメトリクスデータをコピーするため、マイグレーションの間は最大で 2 倍のストレージが必要になります。コピーするデータ量を減らすには、管理パネルの *Configuration* → *Maintenance* で、メトリクスの保持期間を一時的に短くすることを検討してください。設定した保持期間内に収まる過去のデータだけが移行されます。

* データベースのマイグレーションは、より広い概念である*初期化タスク*に統合されました。その結果、次の設定プロパティの名前が変更されました。

    | 変更前 | 変更後 |
    |:-------------------------------|:-------------------------------|
    | `database.run.migrations`      | `init.tasks.enabled`           |
    | `database.run.migrations.only` | `init.and.exit`                |
    | `database.migration.url`       | `init.tasks.database.url`      |
    | `database.migration.username`  | `init.tasks.database.username` |
    | `database.migration.password`  | `init.tasks.database.password` |
