# v5.2.0 へのアップグレード

* **サービスアカウントが `svc:` というユーザー名の接頭辞を予約します**。このリリースでは[サービスアカウント][access-control-svc]が追加されます。ユーザー名が `svc:` で始まる既存のユーザーは、大文字と小文字の違いを問わず、この予約と衝突します。

    そのようなユーザーが存在する場合、データベースのマイグレーションは失敗し、そのエラーメッセージに影響を受けるユーザーが表示されます。アップグレードの前にそれらのユーザーを見つけるには、データベースに対して次のクエリーを実行します。

    ```sql
    SELECT "USERNAME", "TYPE" FROM "USER" WHERE "USERNAME" ILIKE 'svc:%';
    ```

    影響を受ける管理対象ユーザーは、名前を変更するか削除してください。影響を受ける LDAP と OIDC のユーザーは、ID プロバイダーで名前を変更してから Dependency-Track から削除してください。アップグレード後は、`svc:` で始まるユーザー名での LDAP と OIDC のログインは失敗し、REST API はこの接頭辞を持つ新しいユーザーを拒否します。

    チーム API キーは変更なしでそのまま使えます。

* **Cargo のパッケージメタデータをスパースインデックスから取得します**。以前のバージョンは、レート制限のある crates.io API に問い合わせていました。Cargo のリゾルバーは代わりに[スパースレジストリインデックス][cargo-idx]を読み込むようになりました。スパースレジストリインデックスは、レート制限のない CDN から配信されます。データベースのマイグレーションにより、デフォルトの `crates.io` リポジトリの URL が `https://crates.io` から `https://index.crates.io` に変更されます。ただし、その URL を変更していた場合は変更されません。外向きの通信を制限しているデプロイでは、`index.crates.io` を許可する必要があります。

    カスタムの Cargo リポジトリの URL は変更されません。それぞれのリポジトリを、そのレジストリのスパースインデックスに向けてください。たとえば、Cargo の `config.toml` で `sparse+` 接頭辞の後に続く URL です。詳しくは、Cargo の [Using an Alternate Registry][cargo-alt-reg] ガイドを参照してください。

    リゾルバーは、Cargo と同様に、Cargo リポジトリのトークンを `Authorization` ヘッダーにそのまま送信するようになりました。以前のバージョンは `Bearer` 接頭辞を付けていました。レジストリが接頭辞を必要とする場合は、設定したトークンに接頭辞を追加してください。ユーザー名を設定したリポジトリは、引き続きBasic 認証を使います。

* **API サーバーが外向きの接続を制限します**。[`dt.outbound.allowed-destinations`][allowed-destinations] を参照してください。連携先が `localhost` に接続する場合(たとえば Trivy のサイドカー)は、`localhost` を追加してください。すべてのループバックアドレスを許可する `loopback` よりも、正確なホスト名を指定することをお勧めします。この制限は、通知、データソース、パッケージリポジトリ、脆弱性アナライザー、および DefectDojo などの連携に適用されます。

* **`allow-local-connections` プロパティは存在しなくなりました**。これは、メールと Kafka の通知パブリッシャー、OSS Index 脆弱性アナライザー、および NVD と JVN の脆弱性データソースに影響します。設定の誤りに気付かないままになることを防ぐため、設定でこれらのいずれかがまだ設定されている場合、API サーバーは起動を拒否します。これらは [`dt.outbound.allowed-destinations`][allowed-destinations] に置き換えられました。

* **API が BOM と VEX のアップロードにサイズの上限を設けます**。[`dt.bom-upload.max-size-bytes`][max-upload-size-bom] と [`dt.vex-upload.max-size-bytes`][max-upload-size-vex] を参照してください。どちらのプロパティもデフォルトは 100 MiB です。インスタンスでそれより大きいドキュメントを処理する場合は、値を引き上げてください。

* **API サーバーのコンテナーイメージに `curl` が含まれなくなりました**。イメージのヘルスチェックは `wget` を使うようになりました。ヘルスチェックを上書きしている場合や、`exec` プローブで `curl` を実行している場合は、`wget` に切り替えてください。

    ```shell
    wget -q -Y off -T 3 -O /dev/null http://127.0.0.1:9000/health
    ```

    Kubernetes では、ポート `9000` に対する `httpGet` プローブを使えば、イメージにツールはまったく必要ありません。

* **API サーバーのコンテナーイメージに Google Cloud SQL のソケットファクトリーが含まれなくなりました**。データベースの URL で `socketFactory=com.google.cloud.sql.postgres.SocketFactory` を設定している場合、アップグレード後に API サーバーはデータベースに接続できなくなります。[Google Cloud SQL][cloud-sql] の説明に従ってソケットファクトリーを追加してください。
